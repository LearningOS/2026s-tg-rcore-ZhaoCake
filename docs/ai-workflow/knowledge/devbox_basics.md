# 什么是 Devbox（面向本项目）

## 1. 一句话理解

Devbox 是在 Nix 之上的一层开发体验工具：
它用更简单的配置文件来声明依赖，让团队更容易复现开发环境。

## 2. 它和直接用 Nix 的区别

### Devbox 的优势

- 上手快：通常写 `devbox.json` 就能开始。
- 团队可读性好：不需要每个人都熟 Nix 语言。
- 任务管理方便：可定义脚本并统一执行。

### Devbox 的局限

- 遇到底层问题还是要回到 Nix 排障。
- 高级定制（overlay、复杂 override、跨系统输出）不如纯 flake 灵活。

## 3. 对本仓库的建议

本仓库目前优先目标是降低复杂度，因此建议：

- 首选 `flake.nix + .envrc` 方案（简单直接，和现有文档一致）
- Rust 用 rustup 管理（跟章节 `rust-toolchain.toml` 保持一致）
- 仅对 QEMU 做历史版本 pin（本项目使用 qemu 7.2.1）

## 4. 什么时候再考虑 Devbox

当你有下面需求时再引入更合适：

- 多语言工具链统一管理（前后端 + 系统开发）
- 团队成员不熟 Nix，需要更低门槛入口
- 希望统一任务入口（类似 `npm run` 风格）
